# Домашнє завдання №1

## Основи комп'ютерних мереж

---

## Завдання 1. Дослідження мережі

**Мета:** визначити основні параметри мережевого підключення.

### Команда

```bash
ip a
```

### Результат

```text
11: eth0@if21: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 65535 qdisc noqueue state UP group default
    link/ether e2:ed:87:48:77:fa brd ff:ff:ff:ff:ff:ff link-netnsid 0
    inet 172.17.0.2/16 brd 172.17.255.255 scope global eth0
       valid_lft forever preferred_lft forever
```

### Аналіз

| Параметр                        | Значення                                         |
| ------------------------------- | ------------------------------------------------ |
| Інтерфейс                       | `eth0`                                           |
| Тип підключення                 | Ethernet, віртуальний мережевий інтерфейс Docker |
| MAC-адреса                      | `e2:ed:87:48:77:fa`                              |
| IP-адреса                       | `172.17.0.2`                                     |
| Рівень OSI                      | 3-й — мережевий                                  |
| Маска підмережі                 | `/16` (`255.255.0.0`)                            |
| Gateway                         | `172.17.0.1`                                     |
| Broadcast                       | `172.17.255.255`                                 |
| Кількість можливих адрес хостів | 65 534                                           |

**Пояснення:** IP-адреса `172.17.0.2` є локальною адресою контейнера в мережі Docker `172.17.0.0/16`.

## Завдання 2. Дослідження маршрутизації

**Мета:** переглянути таблицю маршрутизації та визначити шлюз за замовчуванням.

### Команда

```bash
ip r
```

### Результат

```text
default via 172.17.0.1 dev eth0
172.17.0.0/16 dev eth0 proto kernel scope link src 172.17.0.2
```

### Аналіз

| Параметр           | Значення        |
| ------------------ | --------------- |
| Gateway            | `172.17.0.1`    |
| Інтерфейс          | `eth0`          |
| Мережа             | `172.17.0.0/16` |
| Локальна IP-адреса | `172.17.0.2`    |
| Джерело маршруту   | `proto kernel`  |

**Пояснення:** `proto kernel` означає, що маршрут до безпосередньо підключеної мережі був створений ядром Linux. У цьому випадку `kernel` позначає джерело маршруту, а не протокол отримання IP-адреси.

## Завдання 3. Знаходження публічної IP-адреси

**Мета:** визначити публічну IP-адресу та порівняти її з локальною.

### Команда

```bash
curl ifconfig.io
```

### Результат

```text
195.64.239.74
```

### Порівняння

| Тип адреси         | IP-адреса       |
| ------------------ | --------------- |
| Локальна IP-адреса | `172.17.0.2`    |
| Публічна IP-адреса | `195.64.239.74` |

**Чи збігаються адреси?** Ні.

### Чому адреси відрізняються?

Локальна IP-адреса `172.17.0.2` використовується всередині приватної мережі Docker і не доступна безпосередньо з Інтернету.

Під час виходу в Інтернет трафік проходить через Docker, операційну систему та домашній роутер. Для зовнішніх ресурсів з'єднання відображається з публічною IP-адресою.

Для перетворення приватних адрес на адресу, яка використовується для доступу до Інтернету, застосовується механізм **NAT (Network Address Translation)**.

---

## Висновок

Під час виконання роботи було досліджено мережевий інтерфейс, таблицю маршрутизації та визначено локальну й публічну IP-адреси. Локальна та публічна IP-адреси відрізняються через використання приватної мережі та механізму NAT.
